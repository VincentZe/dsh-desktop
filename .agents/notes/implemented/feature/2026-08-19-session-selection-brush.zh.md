# Agent Note: 通过按住指针刷选可见会话

Status: implemented

[English](2026-08-19-session-selection-brush.md) | 中文

## Problem

多选时必须逐条点击 Session 行，连续选择一组会话需要频繁移动指针。

## Decision

选择模式持有一个临时的指针刷选状态。在可选 Session 行上按住 `Shift` 或 `Ctrl` 按下鼠标左键会记录起始行和操作类型，并立即并入或移除起始行；指针划过的所有可见行都会被处理。`Shift` 会并入当前选择，`Ctrl` 会从当前选择中减去；不按这两个修饰键则保留普通行点击或重排序拖拽行为。刷选手势产生的合成 click 会被抑制，选择模式中的普通点击仍保留原有的单行切换行为。

复选框、行菜单和其他行操作控件不会启动刷选。回收站行和空白占位行仍然不参与刷选，指针释放或取消时会清理临时状态。

## Alternatives considered

**使用只在选择模式生效的刷选。** 捕获选择模式中的所有主指针拖动会阻止普通 Session 重排序；要求按住 `Shift` 或 `Ctrl` 才刷选，可以在无修饰键时保留重排序。

**使用延迟长按计时器。** 计时器会在手势生效前增加任意等待，使普通点击变得迟钝；修饰键配合按住鼠标左键已经足以区分刷选和点击。

**根据起始行和当前行执行范围选择。** 分组视图和平铺视图可以独立排序，也不共享一个连续记账；按指针实际划过的可见行选择，不会引入用户看不到的排序语义。

**切换每一条经过的行。** 切换会让结果依赖已有选择状态，并可能意外取消会话；显式区分并集和减集后，手势结果更可预测。

## Verification

`packages/client/ui-workspace/tests/workspace-browser.client.spec.tsx` 覆盖直接 `Shift` 刷选、`Shift` 并集、`Ctrl` 减集、不按修饰键时保留拖拽、刷选结束后的 click 抑制以及普通单行切换。WorkspaceBrowser 和 Rows 聚焦套件分别通过 46 和 26 个测试，其中包含修饰键手势抢在原生拖拽前生效的回归测试；tree 套件及 `pnpm run typecheck` 均通过。

## Consequences

该行为同时适用于分组和单列表 Session 视图，但只作用于当前实际渲染且被指针划入的行。Shift 或 Ctrl 刷选会进入选择模式；未按住这两个修饰键时仍可执行普通 Session 拖拽排序，按住修饰键的拖拽会在进入排序处理前被取消。需要小范围调整时，继续使用单行点击或复选框。
